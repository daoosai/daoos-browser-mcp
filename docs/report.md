## Реализованная архитектура

Один Python/FastAPI-процесс с официальным MCP SDK, persistent command actor,
Playwright и headed Chromium. Для сессии запускаются Xvfb и x11vnc: MCP и noVNC
управляют одним браузером, управление передаётся с блокировкой агента.
Изображения — реальные пиксели этого дисплея, возвращаемые MCP ImageContent.
Собственного ИИ-движка нет; планирование остаётся у внешних агентов.

PostgreSQL хранит владельцев, ключи, сессии, задания, действия, квоты и журнал
потребления. Профили шифруются; session cookies дополнительно сохраняются при
штатном закрытии. После сбоя записи сохраняются, утраченные браузеры помечаются
lost, незавершённые действия uncertain и автоматически не повторяются.
Отдельный egress proxy проверяет DNS/IP и ограничивает сетевой доступ.
Подробности: [architecture.md](architecture.md).

## Команды

`browser_read`: methods, status, sessions, tabs, snapshot, screenshot, inspect,
console, network, task_status, task_result, usage, profiles.

`browser_write`: create_session, navigate, click, fill, type, select, scroll,
press_key, switch_tab, new_tab, upload_file, download_file, wait, execute_steps,
cancel_task, close_session, delete_profile, request_approval, resume_task.

Точные схемы публикует methods. Изменяющие запросы требуют request_id;
потенциально изменяющие данные взаимодействия — одноразовое подтверждение
оператора, привязанное к параметрам и странице. Пароли вводятся вручную в VNC.

## Проверка CRM

Реальный переход через MCP на `https://oknakomfort72.ru/crm/`: HTTP 200,
заголовок **«Диалоги · Окна Комфорт CRM»**. Получены настоящее изображение,
DOM/ARIA, основные доступные элементы и диагностика сети/консоли.

Страница показывает «Не удалось открыть CRM», «Требуется вход», поле
«Пароль владельца» и кнопку «Войти». Зафиксированы два сетевых ответа 401 и
ошибки консоли; чувствительные сообщения исключены из ответов. Авторизация
не выполнялась. Меню, разделы и диалоги за авторизацией не проверены.
Заказы не создавались, сообщения не отправлялись, бизнес-данные не изменялись.
Снимки и сырые отчёты хранятся приватно, в Git не добавлены.

Ручное управление и сохранение авторизации доказаны на отдельном тестовом SPA,
а не на авторизованной CRM. Для завершения CRM-проверки оператору нужно войти
через защищённый noVNC, вернуть управление, затем проверить меню и повторное
открытие сохранённого профиля без изменения данных.

## Проверки и безопасность

Финальный unit-прогон: **43 passed**, два предупреждения deprecated WebSocket
API библиотек. Реальный интеграционный прогон: **10 проверок пройдены**:
discovery, CRM без записей, SPA/DOM/MCP PNG, full-page/element PNG,
идемпотентность, одноразовое подтверждение, reconnect, асинхронные задачи,
VNC handoff с реальным RFB-событием и возвратом Playwright,
зашифрованный профиль с session cookie и localStorage.

После удаления тестового контейнера и внутреннего сетевого исключения финальный
образ повторно проверен через приватный MCP: создание сессии, открытие CRM,
настоящее MCP-изображение и закрытие прошли. `/health` — 200, MCP без ключа — 401.
Временные ключи дополнительного теста отозваны. Этот успешный прогон не снимает
отмеченные ниже ограничения ресурсов и незавершённую проверку второго пользователя.

Дополнительный live-прогон второго пользователя: доступ к чужим сессии,
профилю, заданию и снимку отклонён. Запуск нового браузера дважды завершился
таймаутом на этом хосте; проверка отсутствия чужих cookies/localStorage через
новый браузер не завершена. Это открытое ограничение приёмки. Исправлено
маскирование исходной ошибки запуска ошибкой очистки, добавлен regression test.

Unit-тесты также проверяют владельцев, API-аутентификацию, URL/IP ограничения,
PKCE и повторное использование кода, квоты, восстановление записей после сбоя,
таймауты и отказ опасных команд. Живое аварийное отключение контейнера и
восстановление резервной копии не проверялись. Full-page проверен на тестовой
странице; длинные динамические страницы требуют отдельного приёмочного прогона.

`pip-audit` для зафиксированных Python-зависимостей: известных уязвимостей не
обнаружено. Это не аудит ОС, Chromium или ядра. Native Chromium sandbox включён;
внешние порты VNC, X11, PostgreSQL и CDP не публикуются. Ключи и профили не в Git.
Ограничения перед коммерческой эксплуатацией: [security.md](security.md).

## Ресурсы

Хост: 1 CPU, 3911 MiB RAM; swap 2047 MiB занят целиком. Во время дополнительного
прогона доступно около 776 MiB RAM, на диске 2.4 GiB. Это общий production-хост,
ресурсы меняются из-за других приложений.

Docker stats во время проверки: Browser 439.1 MiB / 768 MiB, CPU 11.86%;
egress 32.71 MiB / 64 MiB, CPU 0%; PostgreSQL 19.6 MiB / 128 MiB, CPU 0.01%.
Отдельный cgroup-сэмпл Browser: current 747 MiB, peak около 768 MiB,
CPU 51.39 секунды с запуска контейнера; это включает кэш и отличается от
Docker working-set. На момент измерения OOM и OOM-kill равны нулю, есть
ограничение памяти и CPU throttling. Запас мал; повышение числа сессий не
рекомендуется без ресурсов и нагрузочного теста. Настроена одна активная сессия.
Лимиты CPU: Browser 0.75, egress 0.15, PostgreSQL 0.15.

## Учёт, Billing и оставшаяся работа

Учёт browser_seconds, actions_count, sessions_count, tasks_count,
screenshots_count; CPU/RSS семплируются при доступности. События связаны с
владельцем/организацией и сессией/задачей, где применимо. Уникальные ключи
событий защищают от повторного начисления; ключевые и пользовательские квоты
проверяются на сервере. Последний интервал перед аварией может быть утрачен.

Есть BillingProvider и отключённая реализация NoPayments. Реальные платежи
отсутствуют. Для подключения провайдера нужны отдельные ledger расчётов,
webhook/idempotency, тарифы и финансовая сверка; текущий журнал — основа,
а не готовая платёжная система.

Осталось: согласовать и включить HTTPS route; проверить ChatGPT OAuth и
изображения; выполнить ручной вход и безопасную авторизованную CRM-проверку;
зарегистрировать Core/OpenClaw; настроить внешнее резервное копирование и
проверить восстановление; провести аварийный и нагрузочный прогоны; выделить
отдельный origin и усилить межарендаторную изоляцию перед коммерческим запуском.
Инструкция эксплуатации: [operations.md](operations.md).
